# 将棋の道しるべ

１級から初段を目指す人のための、分岐から学ぶ将棋定跡サイト。

公開先: https://aaaanwz.github.io/shogistudy/

## できること

- 先手／後手と相手の出方を、接続線のあるフローチャートで選択
- 15レッスン：石田流本組、早石田、新石田流の入口、無理矢理早石田と角飛車交換、三二飛戦法の２分岐、後手ノーマル三間飛車、後手石田流の失敗例、および相手からの角交換に対する６分岐
- 盤面・持ち駒・成り駒の表示、前後移動、最初／最後、自動再生、反転、手順選択、スライダー、矢印キー
- 各手の説明、分岐局面への移動、共通局面から別手順への切り替え
- 各レッスンの三択確認問題と、その後の実戦方針
- 学習済みのローカル保存、局面URLの共有、スマートフォン対応

サーバーやAPIキー、ビルド、実行時の外部ライブラリは不要。HTML/CSS/JavaScriptのみで動きます。学習記録は利用者のブラウザー内だけに保存します。

## 相手から角交換された場合

フローチャートには次の６レッスンを追加しています。各教材に一手ごとの説明、確認問題、参考資料があります。

- 本組に組む前の４手目△８八角成：▲同飛から向かい飛車へ方針変更。
- 本組の入口で▲６六歩を省いた場合：△４二玉型での角交換に▲５八玉から反撃。
- 早石田の△８八角成〜△４五角：▲７六角に△２七角成なら馬を作り合う。
- 同じ▲７六角に△４二玉なら：▲３八金で守り返す。
- 三二飛戦法の▲２二角成〜▲６五角：△７四角に▲４三角成なら馬を作って引く。
- 同じ△７四角を▲同角と取られたら：角交換を重ね、７筋の歩で反撃。

角道を止めた本組の駒組み中には、そのまま△８八角成とはできません。「本組成立前に交換された場合」と「本組の入口で角道を止めなかった場合」を区別しています。

## ローカルで動かす

Node.js 22以上とPython 3を用意します。

```sh
npm start
# http://localhost:4173/
```

`site/index.html` を直接 `file://` で開かず、HTTPサーバーを使ってください。

## 検証

```sh
npm run check
python3 -m venv .venv
.venv/bin/pip install -r scripts/requirements-test.txt
.venv/bin/python scripts/validate-moves.py
```

Nodeのテストは教材・分岐の参照整合性、再生状態の不変性、駒の総数、駒取り・成り・打ち・代表的な不正手を検証します。独立した `python-shogi` により全222手の合法性、全局面の盤面・持ち駒・手番を照合します。

表示用ルール処理は自由対局用の完全なエンジンではありません。千日手、入玉宣言、打ち歩詰めなどの対局判定は実装していません。収録教材は独立検証に通る合法手のみを使用します。合法性検証は定跡の形勢・最善性の保証ではありません。

## GitHub Pages

`.github/workflows/pages.yml` が `main` へのpush時に検証し、成功後に `site/` だけを公開します。PRでは検証のみ実行します。

リポジトリの Settings → Pages → Build and deployment → Source は **GitHub Actions** に設定します。外部依存がないため、サブディレクトリ `/shogistudy/` でも同じファイルが動作します。

## 教材を増やす

表示と教材を分離しています。

| ファイル | 役割 |
| --- | --- |
| `site/js/lessons.js` | 戦法カテゴリ、教材、USI手順、解説、出典、先後別の分岐ツリー |
| `site/js/review.js` | 確認問題、解答、その後の方針 |
| `site/js/shogi.js` | 局面再生、持ち駒、成り、棋譜表記 |
| `site/js/app.js` | UIと学習記録、URL状態 |
| `site/style.css` | PC／スマートフォンの表示 |

居飛車などを追加する場合：

1. `courses` に新カテゴリ（例：`{id:'ibisha', name:'居飛車', sides:[0,1]}`）を追加。
2. `lessons` に一意なID、カテゴリID、先後、`moves`、解説、`sourceIds`、`branchAt` を追加。各手は `{usi:'7g7f', note:'説明'}`。全教材は平手初期配置からの交互の手順です。
3. `trees[カテゴリID][先後]` にツリーを追加。途中ノードは `children`、終端は `lesson` で教材IDを指定。
4. `reviews[教材ID]` に `ply`、問題、選択肢、正解番号（0始まり）、解説、方針を追加。
5. 上記２種類の検証を実行。両方の手番に教材がある状態で公開。

URL例：`#lesson=shin&ply=12`。手順と解説を配列から読み込むため、盤面の表示処理を変更せず教材を追加できます。

## 教材の扱い

各教材内に参考リンクを表示しています。代表的な定跡の入口・説明用駒組み例・失敗例を区別し、文章は本サイト用に作成しています。すべての応手を網羅してはいません。エンジン評価や棋士監修を受けた教材ではなく、特定の手順での勝ちを保証するものでもありません。
